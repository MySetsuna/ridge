# Ridge iteration 3 报告

生成时间：2026-07-21 12:55:59 +08:00  
主题：Cloud Remote 确定性 fault-injection 门禁

## 本轮完成

1. 新增跨 `ControllerCloudProvider → CloudWebrtcAdapter → RpcClient` 的真实生产类故障夹具；WebSocket、PeerConnection、DataChannel 仅替换浏览器边界，事件时序、E2EE、重连和 RPC 状态机均走生产实现。
2. 先红后绿发现并修复一个真实授权时序缺陷：Cloud 到达 E2EE `connected`、TOTP 尚未通过时，L2 会提前发送 `$/hello` 和 pane 恢复帧；Host 正确丢弃这些业务帧，但授权完成后没有补发。
3. `RpcClient` 现在以 `transport connected && auth authorized` 作为 business-ready：
   - `hello()` 在未 ready 时只记录意图；
   - 连接或授权恢复后每周期恰好一次重发 `$/hello` 和 resync hooks；
   - LAN 已在 WS upgrade 鉴权，既有行为不变；Cloud 则等待 `0x12 totp-result`。
4. 新门禁覆盖：
   - RTC failure 立即以 `RpcReconnectError` settle 在途 RPC；
   - 信令存活时只做一次 ICE restart，授权前不恢复 pane；
   - 信令失效时重建 PC/DC/WS，重新 E2EE + TOTP 后才恢复；
   - 高水位期间 A/B pane 多次丢帧，drain 后每 pane 恰好一次 resync，C 不串入；
   - fake timers 下固定 100 个 failure/recovery 周期，pending RPC、重复订阅和 timer 均不累积，offer/send 次数精确线性。
5. 共享 Cloud transport/conformance 夹具显式驱动授权完成，避免继续把“RTC connected”误当成“业务可用”。
