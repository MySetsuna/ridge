## 完成事项

1. **G1[T1·主线] `cargo test -p ridge --lib` 宿主载败根修**（commit `ea1f0ae`）：
   - **根因**（PE 导入表解析 + PowerShell `GetProcAddress` 逐符号探测确证）：依赖树引入
     `comctl32!TaskDialogIndirect`——该符号仅 common-controls **v6** 导出。tauri 主 exe 由
     tauri-build 嵌入声明 v6 的 manifest；cargo 的 lib 单测宿主没有 manifest，加载器把
     comctl32 绑到 WinSxS 5.82（无此导出）→ 进程启动即 `STATUS_ENTRYPOINT_NOT_FOUND (0xc0000139)`。
   - **失败尝试留档**：`cargo:rustc-link-arg-tests` 只作用于 `[[test]]` 集成目标，不覆盖 lib
     单测宿主（同 exe 哈希复现）；`/MANIFEST:EMBED` 会与 tauri-build 的 RT_MANIFEST 资源冲突，不可用。
   - **修法**：`build.rs` 全局注入 `/DELAYLOAD:comctl32.dll /DEFAULTLIB:delayimp.lib`——绑定推迟到
     首次真实调用；测试从不弹对话框故永不绑定，主 exe 首调时其 manifest 的 v6 激活上下文已生效。
   - **结果**：`cargo test -p ridge --lib` **92/92 本机首次全绿**（teammate 投影脱敏、hello 能力
     交集等安全断言首次真实执行）；`cargo test --workspace` **首次整仓 exit 0**。附
     `tests/win_manifest_boot.rs` boot smoke 防回归。**T1 由「大部关闭」升为完全关闭**。
2. **G2[R1] 确定性弱网实验室 harness**（commit `8f66e1c`）：
