| 1 | 后台不停启停 git 进程（未开新文件夹也如此） | ✅ 根治 | `core.fsmonitor` 仓库里每次 `git status/diff` 都会在 `.git/fsmonitor--daemon/cookies/` 建删 cookie；`GitWatcher::is_scm_relevant` 未过滤该路径 → 我方 SCM 刷新触发 watcher → 再刷新，**自反馈永动**。实测 idle 时每秒 2–4 个 `git.exe` spawn/kill，父进程 = `ridge.exe`。修：过滤 `fsmonitor--daemon`（+ 回归单测）；SCM 侧 watcher 刷新统一入口 `scheduleWatcherRefresh`（250ms 合并 + 每 repo ≥2s 最小间隔）作第二道防线 |

### 踩坑记录（值得记住）

`main` 上有**另一进程在途**的 `ridge-mcp` crate 抽取（worktree 有改动、crate 未提交）。本轮同步版本号时 `git add src-tauri/Cargo.toml` 连带把它的
`ridge-mcp = { path = "../packages/ridge-mcp" }` 带进提交 → CI `cargo metadata` 直接红：

```
failed to load manifest for dependency `ridge-mcp`
failed to read `.../packages/ridge-mcp/Cargo.toml`
No such file or directory (os error 2)
```

教训：**共享仓库里提交前逐文件看 diff，别按路径批量 `git add`**——尤其 `Cargo.toml` 这类多方共同触碰的清单文件。修正手法：用 `git hash-object` + `git update-index --cacheinfo` 只改**索引**里的那份（保留工作区中他方在途内容），再重打 tag。
