# Ridge 多智能体协同 · 用户使用手册

> 适用版本：develop（≥ 本次「Domain Zero 端侧多智能体协同」落地后）。需重新构建/安装才能使用本手册描述的能力。

---

## 这是什么

Ridge 不再只是一个「你一个人对着一个终端」的工具。它现在内置了一套**端侧多智能体协同系统**——多个 AI 智能体（Agent）可以在同一个 Ridge 窗口里**分屏协作**：一个当**指挥官（Leader）**统筹，其余当**工人（Worker）**干活；它们之间经内置 MCP 工具**互相发消息、派活、编组**，而你坐在中间，通过一个**数字指挥部**看清全局、并在关键时刻**一键拍板**。

这套系统围绕四件事设计：

| 能力 | 一句话 |
| --- | --- |
| 👁️ **看得见**（数字指挥部 / Agent Center） | 一个侧栏面板，实时显示团队成员名册、编组、异常告警 |
| 🛡️ **拦得住**（安全审批 / HITL） | 智能体要执行危险命令时，弹窗让你**批准 / 拒绝 / 改写**，而不是直接跑 |
| ⚡ **断得了**（循环熔断） | 某个智能体陷入「改→测→报错」死循环时，自动中断它并红色告警，喊你接管 |
| 🔌 **接得上**（内置 MCP server） | 标准 MCP 协议端点，让 MCP-原生的智能体（如 Claude Code）直接挂进来协作 |

---

## 核心概念速览

- **Agent（智能体）= 一个分屏（pane）**：每个跑着 AI 的终端分屏就是一名队员。
- **Leader / Worker / Observer**：角色。Leader 由**极简能力档**自动竞选产生（按 agent 名 / 启动程序关键字被动识别 Base / Skilled / Expert 三档，档最高者当选、同档取 id 最小者），统筹分派；Worker 执行；Observer 旁观。
- **风险分级 L0 / L1 / L2**：每条命令按危险度分三档（只读 / 写工作区 / 危险），是安全审批的依据。
- **编组（Group）**：把若干队员编成一个组，给整组派活时**只发给组长**、由组长统一分派。可在指挥部手动建组 / 加成员，agent 也能经 MCP `ridge_join_group` 自助加入某个按名字寻址的已有组。

## 1. 数字指挥部（Agent Center）

**在哪**：左侧栏底部的「**智能体指挥部**」面板（和「全局状态」并列的全局插件区）。如果看不到，先确认侧栏已展开、且当前有打开的工作区。

面板顶部有一个「**审批**」快捷开关（HITL，见 §2）。往下是这几块：

### 团队花名册（Roster）
列出所有队员：
- 👑 **皇冠**标记的是 **Leader**。
- 每个名字右边有个**状态点**：绿色脉冲 = 工作中（Working），灰色 = 空闲（Idle），暗灰 = 已失联（Disappeared）。
- 成员还带一个**能力档**标记（Base / Skilled / Expert，Leader 竞选依据）。
- 右上角数字 = 团队人数。
- 没有队员时显示「还没有智能体加入」。

### 编组（Group）
把队员编成组、给整组派活（**发给组长**统一分派）。组卡片支持建组 / 改名 / 解散 / **＋加成员** / 给组派任务；agent 也能经 MCP `ridge_join_group` 自助加进已有组，加成功 / 失败会有 toast 轻提示。

> **说明**：底座化瘦身后，早期的「当前目标 / TML 协作审计」等 AI 自治可视化**已退场**——指挥部现在只保留「给人看的」两块（**成员名册** + **异常告警**）外加编组区。智能体之间的协作改由标准 MCP 工具驱动（见 §5），不再有 TML 中间格式。

### 熔断告警（仅异常时出现）
当某个队员被判定陷入死循环并熔断时，这里会**置顶一条红色告警**：
- 🔴 `Hermes 已熔断 · 同一文件 改→测→报错 ×3 (E0277 类型不匹配)`
- 右上角有「**清除**」按钮，你确认接管后点掉即可。

平时无异常时这一栏**完全不显示**，不打扰。

## 2. 安全审批网关（HITL · Human-in-the-Loop）

智能体自动跑命令很方便，但「自动 `rm -rf`」很可怕。安全审批网关就是你的**最后一道闸**。

**开启后**，当任何智能体试图提交一条被判为 **L2（危险）** 的命令时，Ridge 会**挂起那条命令、不让它执行**，并弹出一个居中的审批模态：

```
┌─────────────────────────────────────────────┐
│ 🛡️ 需要你的授权                         [L2]  │
│    来自 pane#2 (claude-code)                  │
│ ───────────────────────────────────────────  │
│ 递归/批量删除                                  │
│ ┌─────────────────────────────────────────┐ │
│ │ rm -rf /tmp/build-cache --no-preserve-root│ │
│ └─────────────────────────────────────────┘ │
│  ✕ 拒绝              ✏ 修改        ✓ 批准      │
└─────────────────────────────────────────────┘
```

你有三个选择：
- **✓ 批准**：放行，命令照常执行。
- **✕ 拒绝**：阻断，向智能体返回「被授权策略拦截」，它不会执行。
- **✏ 修改**：先改写命令（比如给路径加个限定），再执行你改写后的版本。

**特性**：
- 多条待审批会**排队**，模态右上角显示 `+N` 表示后面还有几条。
- 超时未裁决（默认 120 秒）会**自动拒绝**（fail-closed，宁可挡错不可放错）。
- **只拦 L2 危险命令**；L0/L1 直接放行，不打扰你。

> ⚠️ **默认关闭**。开启方式见 §7。关闭时智能体命令照常执行（行为与加这套系统之前完全一致）。

## 3. 风险分级（L0 / L1 / L2）

每条命令在执行前都会被分级，这是安全审批的依据：

| 档位 | 含义 | 例子 |
| --- | --- | --- |
| **L0** 只读 | 不改任何东西 | `ls -la`、`git status`、`cat x`、`grep ...` |
| **L1** 工作区写 | 在工作区内写文件 | `echo hi > out.txt`、`npm install`、改文件 |
| **L2** 危险 | 可能造成不可逆/外部影响 | `rm -rf ...`、`git push`、`curl ... | sh`、`sudo ...` |

分级器**抗绕过**：会先把多余空格归一化（`git   push` 照样判 L2）、识别管道灌 shell（`... | bash`）、重定向覆盖等花招，不会被简单变形骗过。

## 4. 循环熔断

AI 智能体偶尔会卡进「改代码 → 跑测试 → 同样报错 → 再改 → 还是同样报错」的死循环，白白烧 token。循环熔断就是给每个 Worker 装的**保险丝**。

**怎么触发**：当一个队员**连续 3 次**上报**高度相似的失败**（同一个错误特征），系统判定它陷入逻辑死锁，于是：
1. **向那个分屏发 `Ctrl+C`**，强制打断它正在做的事；
2. 在指挥部**置顶一条红色「熔断告警」**（见 §1），告诉你是谁、为什么；

你看到告警后接管那个队员（重新给指令、换个思路、或让 Leader 重新分派），然后点「清除」消掉告警。

> 熔断**默认随队工作**（无需手动开），但只有当队员通过协作 API 上报带「分屏 + 失败特征」的进度时才会计数。阈值（3 次）是内置的。

## 5. 智能体协作（经内置 MCP 工具）

队员之间通过 Ridge 内置的 **MCP 工具**协作，你**通常不用直接碰**——它们由智能体的运行时（如 Claude Code）自动调用。当前已接线（`tools/call` 路由）的协作能力：

- **查花名册（`ridge_get_team_profile`）**：只读取当前工作区的 roster + leader + edges；agent 先调它发现队友，再据成员的 `paneId` / `paneIndex` 寻址。
- **写草稿（`ridge_send_to_teammate`）**：向指定分屏注入文本，但**不**模拟 Enter；返回 `draft_injected`，不等于命令已执行。
- **显式提交（`ridge_send_and_submit`）**：写入文本并派发 Enter；返回 `submit_dispatched`，仍不等于终端程序或 Agent 已消费。
- **派活（`ridge_delegate_task`）**：显式提交目标给某个 Worker，并标记为「工作中」。
- **查回执（`ridge_delivery_status`）**：分别查看草稿/提交、终端写入接受与 Agent 确认；目标 Agent 以 `ridge_acknowledge_receipt` 明确确认或拒绝。
- **加入编组（`ridge_join_group`）**：把某成员（按 `agent_id` 或 pane）加进一个按名字寻址的已有编组。

> 早期的「TML 中间格式 / 广播求助 / 协作审计面板」在底座化瘦身中**已移除**——协作现在是**标准 MCP 工具的直接调用**，没有中间标记语言，也不再有「协作审计」这一栏。完整工具表（含 `ridge_split_pane` / `ridge_stash_data` 等已登记待路由项）见 `docs/mcp-integration.md`。

## 6. 内置 MCP server（高级 / 给开发者）

桌面 Ridge 自带一个标准 **MCP（Model Context Protocol）** 服务端；打开 Ridge 并在它的 pane 内启动 Agent 即可，**无须安装或启动 `rdg`**。Codex 等仅支持 stdio 的客户端使用独立 `ridge-mcp` companion；`rdg` 是另一款无头应用，旧 `rdg mcp` 仅兼容既有脚本。

- **端点**：`ws://<teammate-host>/api/v1/mcp/ws`（teammate 服务的 WebSocket，带 bearer token 鉴权；地址/令牌通过分屏环境变量 `RIDGE_TEAMMATE_*` 注入）。
- **协议**：JSON-RPC 2.0，支持 `initialize` / `tools/list` / `tools/call` / `resources/read`。
- **工具**：`ridge_send_to_teammate`、`ridge_delegate_task`、`ridge_split_pane`、`ridge_stash_data`、`ridge_get_team_profile` 等。
- **资源**：`ridge://workspace/active-panes`（活动工作区花名册）等 `ridge://` URI。

完整接入、HTTP/WebSocket 配置及无头 `rdg` 的独立说明见 `docs/mcp-integration.md`。

普通用户不用关心这一层；它是给「自带 MCP 客户端的智能体」用的标准接入口。

## 7. 开关一览

这套系统里 **安全审批默认关闭**（保证零行为变化、零回归），需要时在设置面板打开；循环熔断随队常驻。

| 能力 | 默认 | 开关 | 说明 |
| --- | --- | --- | --- |
| **安全审批（HITL）** | 关 | 设置面板「安全审批」图形开关（已就绪）／ 或 `set_hitl_enabled(true/false)` | 开后才会对 L2 命令弹审批模态 |
| **循环熔断** | 开（随队工作） | 无开关 | 队员上报失败达阈值即触发 |
| **数字指挥部面板** | 开（常驻侧栏） | 无开关 | 无团队时显示空态，不打扰 |

> 安全审批默认关，是因为它触及命令执行的关键路径——先确保对现有使用**零影响**，待你确认要用再打开。**设置面板已提供图形开关**（早期只能敲 `set_hitl_enabled` 命令的限制已解除）。

## 8. 常见问题（FAQ）

**Q：我看不到「智能体指挥部」面板？**
A：① 确认你用的是包含本能力的新版本（需重新构建/安装）；② 确认左侧栏已展开、且当前有打开的工作区——它在侧栏的全局插件区（底部），跟着工作区一起出现。

**Q：花名册一直是空的 / 显示「还没有智能体加入」？**
A：只有当智能体通过 Ridge 的 teammate 机制**注册**到某个分屏后才会进花名册。你自己手动开的普通终端不算队员。

**Q：我没看到危险命令的审批弹窗，它直接跑了？**
A：安全审批**默认关闭**，需先 `set_hitl_enabled(true)`（§7）。另外它**只拦 L2**，且只拦智能体经协作通道提交的命令——你自己在终端里手敲的命令不走这条审批闸。

**Q：熔断会误伤吗？**
A：只有「连续 3 次**高度相似**的失败」才触发；单次失败、或失败特征不同，都不会熔断。触发后是发 `Ctrl+C` 打断 + 告警，不会杀掉分屏。

**Q：这套东西会拖慢我平时用终端吗？**
A：不会。安全审批网关默认关时是**字节级零变化**；指挥部面板无团队时零渲染。
