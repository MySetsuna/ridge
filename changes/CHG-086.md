# Research and design

User authorized continued local improvements to Remote features, experience and performance. Prior authorization to fill SpecTree change metadata continues. Research found staged and working rows share an uncached diff callback; untracked rows also open empty diffs. SCM status discovers the repository ancestor but reports the requested nested CWD as repo_root, and adapters drop root metadata. File saves clear dirty after a late ACK even if the user continued typing. Viewer provider follows active CWD. Drawer destruction loses navigation. Search only cancels old work when the delayed request starts, leaving a stale-result window. Directory retry uses the last successful path, not the failed target. Non-Git negative cache cannot be refreshed.

Design sequence: preserve canonical root and exact Git comparison; keep temporary navigation and pin viewer source; fence save snapshots and immediate search invalidation; add explicit read retry and non-Git recheck; bound initial rendered lines to 200 while retaining complete text. Reuse current Query keys, data adapters, permission checks and error paths. No new service, persistence or provider session. Approved scope follows the user's instruction to continue improving the existing local product; no new security or deployment authority is inferred.

Acceptance: real owned Kernel/files/Git through production Remote components; directory/search round trips, forced refresh, delayed reads/saves, index vs working/untracked content, nested-CWD identity, forbidden path rejection and no implicit mutations. Measure a fixed large-file render before/after and repeated tab request counts. Mandatory npm test/lint/typecheck, relevant Rust tests, production build and SpecTree verify/complete. Physical device, external Agent and WAN remain deferred per user preference.

# Implementation and evidence

- Repaired both search adapters against the actual current Kernel contract: LAN search maps `file/content` hits, while the shared desktop/Cloud RPC provider sends flat search arguments. Real Kernel searches now return paths, snippets and exact hit lines.
- SCM now reports the discovered repository root. Git rows resolve their repository-relative paths to exact targets, while RPC commands retain the original authorized CWD. Root discovery never creates a filesystem grant; index mutations still require authorization of the actual repository root. Staged and working previews use distinct cache keys; untracked rows read the actual file. File saves invalidate the same canonical working-diff key used by relative Git rows. Stage/unstage and explicit refresh invalidate both comparisons.
- Directory retry retains the failed target and last successful rows. File/search navigation survives viewer return and tab remount, resetting when the session, workspace, pane or CWD changes. Search immediately invalidates obsolete results before debouncing and fences late responses. Explicit read retries reuse existing Query keys; ordinary warm reads stay cached. Manual Git refresh rechecks a previously non-Git directory.
- Viewer captures its provider, path and submitted save snapshot. A late ACK cannot clear newer typing or alter another target. Offline/disposed LAN requests fail immediately without queuing writes for reconnection. Failed saves preserve the buffer; close/refresh retain dirty confirmation and are disabled while saving. File/image retry uses authenticated endpoints; the development proxy now forwards `/file` and `/session`.
- Large-file reading initially renders 200 rows and extends on demand, keeping the existing 5,000-row display limit and complete text for editing, copying and saving. No new runtime dependency, persistence service or permission widening.

`scripts/remote-tabs-acceptance.mjs` runs the actual Remote development app against an owned current Kernel through the real TLS/WSS proxy. It uses temporary files/repositories and a local bare push destination, captures explicit fault injection separately from successful real IO, and tears down its browser, server and Kernel. Final run passed all 16 scenarios, including nested-CWD index/working/untracked previews, cached-diff invalidation after editing, delayed and failed searches/saves, actual offline/reconnect/manual-save behavior, forbidden paths, initial index-write denial followed by an explicitly authorized root source, stage/unstage, canceled and accepted commit, local push, lazy graph, source-change reset, non-Git recheck, and the single Host-global Commune group authority. Four warm files/search/Git cycles caused zero additional data RPCs. Evidence: ignored `artifacts/remote086/acceptance.json` and `browser-verified.log`.

Fixed rendering benchmark: the component at `780779a0` and the current component rendered the same 4,800-line in-memory text, six alternating samples each, measured through two animation frames. Median initial render was 349.0 ms / 4,800 rows before and 33.35 ms / 200 rows after (ranges 298.5-369.3 ms and 21.4-34.6 ms). Chromium used software WebGL on this host. This isolates initial text rendering; it is not a phone, WAN, Cloud-network or whole-application performance claim.

Validation: SpecTree verify with repository tests passed, unauthorized paths were empty and trace coverage was 1. Final npm lint/typecheck reported zero errors and warnings. Targeted transport/sidebar tests passed 35 cases. Windows Core tests passed 375 with one ignored; real remote invoke integration passed three. Linux Core tests passed 373 with one ignored. Remote desktop/mobile production builds and the PWA output check passed. Logs remain under ignored `artifacts/remote086/`.

Extended Rust verification exposed two pre-existing test-harness gaps: Git-spawn auditing incorrectly included Cargo integration fixtures, and theme tests redirected only Windows data paths. The audit now exempts Cargo integration fixture trees while still checking production `src/tests` modules. Theme tests use the platform-independent Kernel data override. The initial Linux run had written a known damaged fixture to the WSL user's theme document; its bytes were preserved in a backup, and the document was atomically restored from the earliest preserved valid archive. Subsequent fixed Linux tests left that restored document valid and unchanged. No claim is made that the entire user data directory was restored to a prior snapshot.

Physical phone lifecycle/touch/IME behavior, real external Agent endpoints and WAN/Cloud connectivity remain deferred by the user. The shared Cloud RPC adapter was exercised over local RPC, not an actual Cloud network. Version remains 0.1.97; this change does not publish a release.
