# Honor existing kernel pane IDs in LAN host lifecycle

The kernel-backed LAN host shall honor the desktop browser's existing-pane
`create_pane` lifecycle. When `paneId` identifies a leaf already present in
the requested workspace, the host must create the PTY for that stable ID if
needed and acknowledge it idempotently when already running; it must not
split the workspace or return a different pane ID. The no-`paneId` path
remains the explicit split/new-pane operation.

Acceptance:

- Existing layout pane creation preserves the requested ID and session count.
- Repeating existing-pane creation is idempotent.
- `activate_pane_pty` settles and `write_to_pty` reaches the requested pane.
- No-`paneId` create still splits and creates one new PTY.
- Real headed browser E2E passes desktop sent/echo/page-feed IO, resize,
  reload reconnect, and A→B→A isolation gates.
- `pnpm test`, `pnpm lint`, `pnpm typecheck`, `stc verify`, and `stc complete`
  are run and reported.
