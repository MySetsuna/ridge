# Keep remote WebSocket input responsive during blocking kernel calls

## Semantic delta

The LAN host WebSocket loop shall not execute synchronous kernel-domain calls
inline on its receive/send loop. Blocking dispatches, including PTY input,
must run in blocking tasks and return their result through the same wire
envelope, so browser keyboard input and output subscriptions remain live while
one kernel request is slow or bounded by its timeout.

## Acceptance tests

1. A real headed browser keyboard sequence sends the complete unique marker,
   receives the invoke result, and observes shell echo plus desktop feed.
2. A slow or failed blocking dispatch does not prevent subsequent WebSocket
   frames, ping/pong, or output subscription delivery.
3. Existing auth, pane identity, resize, detach/reconnect, and error response
   semantics remain unchanged.
