# emoji 形状不规则

## Confirmed defect

- Color emoji quads use each glyph's tightly cropped native bitmap dimensions.
  Faces and decorated emoji therefore jump between visibly different sizes at
  one terminal font size even though their graphemes reserve the same cells.
- Keeping the full native bitmap fixed clipping, but left size and alignment
  dependent on each platform glyph's painted bounds.

## Semantic delta

- Normalize every color-emoji grapheme to one stable em-sized render box.
- Preserve the source bitmap's aspect ratio and complete atlas UV rectangle;
  scale the whole glyph instead of cropping ornaments or ZWJ components.
- Center the normalized glyph in its terminal row and reserved cell span while
  retaining the parser's existing grapheme width and following-cell position.
- Keep monochrome text, CJK, box drawing, and geometric-symbol geometry native.
- Keep screen composition on WebGPU and use the operating system emoji fallback;
  Remote and Cloud clients require no bundled or separately installed font.

## Acceptance

- Deterministic geometry tests prove undersized, oversized, and non-square color
  bitmaps share one maximum em extent, preserve aspect ratio, retain full UVs,
  and remain centered without clipping.
- Deterministic tests prove monochrome glyph geometry is unchanged.
- Adjacent ASCII starts at the same terminal cell after single-codepoint,
  variation-selector, decorated, and ZWJ emoji clusters.
- Focused ridge-term tests, the WASM build, and `stc validate` pass.
- In the running `dev:cdp` terminal, a mixed emoji fixture renders without
  visible size jumps or clipping at the active Windows device scale.
