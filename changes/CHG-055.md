# CHG-055 — Ridge ACP M2.1 NS-2 Desktop Tauri Bridge

## §1 Scope

Thin bridge layer between ridge-acp's `AgentSession` and the existing Tauri
desktop app. Bridge does NOT hold business state — `AgentSession` is the
single source of truth for session/message/tool/approval state.

- **src-tauri/src/bridge/acp_bridge.rs** (new) — `AcpBridgeState` + 7 Tauri commands
- **src-tauri/src/bridge/mod.rs** (new) — module declaration
- **src-tauri/src/lib.rs** — add `mod bridge;` + `.manage(AcpBridgeState::default())` + 7 `tauri::command` registrations in `tauri::generate_handler!`
- **src-tauri/Cargo.toml** — add `ridge-acp = { path = "../../packages/ridge-acp" }`

## §2 NOT in scope

- src-tauri/** runtime/PTY/teammate code (frozen by L2-REMOTE-MOBILE-SEMANTIC-V2)
- Bridge holds NO message/tool/approval list — events flow through AgentSessionEvent broadcast only
- New ACP adapter types (use ridge-acp's existing `AcpTransport`/`AgentSession`)
- Tauri event subscription cleanup logic in JS land (handled by frontend unmount)
- Approval UI (M2.1 NS-3 deferred)

## §3 Single source of truth

```
AgentSession
   ↓ AgentSessionEvent (broadcast)
forward_session_events task
   ↓ app.emit("acp_event", envelope)
Frontend (renderer)
```

Reverse:
```
Frontend user action
   ↓ invoke("acp_prompt", text)
Tauri command
   ↓ session.prompt(text)
AgentSession
   ↓ prompt_loop
AcpTransport
   ↓ stdio JSON-RPC
opencode-acp binary
```
