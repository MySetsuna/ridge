# Align LAN host pane lifecycle with desktop browser RPC

The headless LAN host shall honor the desktop browser's existing-pane
`create_pane` lifecycle. When the invoke carries a valid `paneId` already
present in the host workspace, the host must acknowledge that pane without
allocating a second session; `activate_pane_pty` and subsequent
`write_to_pty` for that pane must settle and reach the pane's PTY. The legacy
no-`paneId` create path remains an explicit new-pane allocation for clients
that use it.

Acceptance:

- Existing-pane `create_pane` returns success without changing session count.
- Existing-pane `activate_pane_pty` returns success, and `write_to_pty`
  reaches that pane.
- No-`paneId` `create_pane` keeps allocating one new session.
- The real browser E2E desktop path passes the sent/echo/page-feed IO gates,
  resize, reload reconnect, and pane isolation checks.
- `pnpm test`, `pnpm lint`, `pnpm typecheck`, `stc verify`, and `stc complete`
  are run and reported.
