# AVD-based acceptance scripts for §12.6 device categories

为 §12.6 六类设备验收补 AVD（Android Virtual Device，Pixel_9_Pro_XL，
Android 16）可自动执行验证脚本：当真机不在场时，用 `adb input tap/swipe`
驱 AVD Chrome 进 SPA 真实路径。约束沿用既有：

- 不 mock output（PTY 字节仍自真 host 出）
- 不绕过 transport（仍走 L1/L2 真实信道）
- 不杀安装版 ridge（PIDs 17384/17584 全程未触）
- 证书仅做 SPKI pin (`--ignore-certificate-errors-spki-list=<hash>`)，
  非全量忽略

新增四脚本（每条各对应一 L4 spec node）：

- `scripts/avd-adb.ps1` — PowerShell 包装，规避 MSYS 路径吞噬对
  `adb shell /data/...` 的改写
- `scripts/avd-auth-and-probe.mjs` — 启动隔离 host（端口 5120、
  `RIDGE_KERNEL_DATA_DIR` 临时目录），抓 TOTP，强停 Chrome 重拉 SPA，
  swipeTap + screencap 验通
- `scripts/avd-cats.mjs` — 硬编码坐标驱动 6 类交互（侧栏手势 /
  滚动 / IME / PWA 菜单），因 `uiautomator` 看不到 WebView 按钮
- `scripts/avd-acceptance.mjs` — 更早的初始 driver，保留作历史参考

每条 §12.6 类别记录一张证据 PNG 至
`artifacts/release/avd-acceptance/`。§12.6 文档补
"12.6.x AVD 验收" 小节，含分类结果、AVD 限制（test-rdg 无真 shell，
pane 为空）、清理说明（`pm clear com.android.chrome` 会清掉
`/data/local/tmp/chrome-command-line`）。

## Acceptance tests

1. §12.6 6 类别在 AVD 上均产出至少一张 screencap。
2. C1（离线/锁屏恢复）与 C2（侧栏手势）在 AVD 上 PASS。
3. C3 / C5 / C6 因 AVD 限制或输入焦点缺失记为 PARTIAL，写明原因。
4. C4 未跑（多指触控复杂，AVD 上 `input` 不便模拟），记 NOT_RUN。
5. TOTP 在 30 s 窗口内输入完成；超窗脚本显式退出 1。
6. 脚本不动安装版 ridge PID。
