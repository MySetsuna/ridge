# Research and design

User requested further locally verifiable Remote and Commune improvements. Prior authorization to fill change metadata continues. Code review found Cloud forwards group/task/approval events but omits member/session events; the narrow roster also omits member events. Thus quiet terminal members/replies can remain stale. Repeated refresh starts abort prior observers and can starve slow reads. History input only increments its request generation after debounce, so old reads can replace new-query results; event refreshes can interrupt paging and text browsing. Global history merge schedules all-source Promise batches for every consumed row even when buffers are full.

Keep existing Host-global authority and exact source identities. Complete event parity, coalesce/serialize roster updates with one pending follow-up and deliberate cache invalidation. Fence history input immediately, serialize live refresh behind active reads, retain earlier-history slices with the existing new-events indicator, and validate text-page identity. Fill only empty source buffers, bounded to four concurrent reads. No new protocol, persistence, permission grant, Agent session or runtime dependency.

Acceptance: regression tests for both adapter events, source-filtered refresh and opaque cursor ordering; actual production desktop/narrow history/roster components against an owned current Kernel and existing protocol process fixtures, with explicit delayed/error injection. Measure fixed multi-source pagination before/after. Run npm test/lint/typecheck, Remote builds and SpecTree verify/complete. Phone, WAN/hosted Cloud and actual external Agent acceptance remain deferred by the user.

# Implementation and validation

Cloud now forwards member and session events alongside the existing group/task/approval events, and the narrow roster consumes membership changes. Per-source live refreshes share an active read, coalesce one follow-up, and defer invalidation until that follow-up actually starts. Reconnect and explicit retry invalidate scoped caches. Ordinary remounts retain warm QueryClient snapshots; an immediate capability-subscription snapshot is distinguished from a later capability change. The real QueryClient browser regression caught unnecessary reads in the intermediate implementation and now verifies zero warm-remount reads plus one real reconnect refresh. This repairs quiet updates and avoids repeatedly canceling slow observers. Existing Host-global membership, source filtering, exact identities and Runtime capability checks remain unchanged.

The shared desktop/Remote history view immediately invalidates list and text-page generations when search input changes. Late query/source results cannot replace the current view or clear its unread marker. Text pages must match their selected event/source. Live events queue behind active reads; browsing earlier records or explicit text pages retains the reading position and shows the existing new-activity refresh action. Search/source changes and teardown cancel pending timers. The global merge now fills source buffers once per page and refills only an exhausted selected source; it keeps the existing four-read bound, independent opaque cursors and failure isolation, without prefetching beyond a satisfied page.
