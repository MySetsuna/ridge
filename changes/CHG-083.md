# Wait for committed autosave state before rollback fault injection

Windows v0.1.96 passed all 221 Kernel unit tests and the real PowerShell/cwd integrations, then workspace_file_owner failed its byte-for-byte rollback assertion. The test treated an archive file as successful autosave completion even though archive creation precedes snapshot replacement and graph commit. Its last-history read does not synchronize with the graph writer, so the test can capture uncommitted bytes and interrupt that same save while injecting failure. Read the workspace association through the real info operation after observing the archive, which crosses the writer's graph mutex before taking the baseline and injecting failure. Preserve real subprocess ownership, exact-byte rollback, stale-target checks and retry assertions; do not ignore saved_at or add arbitrary sleeps. Validate repeated Windows release-mode and Linux owner tests, mandatory JS checks and four-platform release gates. Advance product to 0.1.97; retain prior tags and unpublished drafts. User authorization includes validation fixes and the change metadata exception.

Validation: Windows release-mode Kernel 221 unit and 5 integration tests passed with a real 8.3 TEMP/TMP. The owner test then passed 20 repeated Windows release runs and 10 Linux runs. npm test passed 2145 frontend and 6 walker tests (14 existing skips); lint/typecheck passed. CI failure evidence: v0.1.96 run 40307871790, Windows job 121528192586; decoded snapshots differed only in saved_at. The original test passed one local baseline run, so the failure was scheduling-dependent. Read-only review confirmed the graph-lock barrier and retained exact-byte assertions. Logs: artifacts/continuity-20261026/owner083-*.log and final083-js.log.
