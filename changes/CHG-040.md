# Run browser UI E2E headed with real pane readiness

## Semantic delta

The browser E2E harness shall launch Chromium headed and shall gate desktop
session readiness on an actual workspace pane and its attachable terminal
surface, not on a host canvas or a frame-count proxy. Existing real auth,
transport, sent/echo/desktop-feed, resize, reconnect, reload, and pane
isolation assertions remain unchanged.

## Acceptance tests

1. `scripts/browser-ui-e2e.mjs` runs with headed Chromium and normal scoped
   certificate trust; it contains no blanket certificate-error bypass.
2. Desktop readiness waits for a real `[data-rg-pane-id]` or
   `textarea.hidden-input` terminal surface after workspace/pane creation.
3. The existing three-layer marker gates remain required: sent wire data,
   shell echo, and desktop `manager.feed`/render evidence.
