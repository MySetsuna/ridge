# Fix Remote mobile IME focus, viewport refresh, and atomic lazy scrollback

Mobile terminal taps retain the hidden IME sink as the focused element, so the
browser's synthetic compatibility click cannot collapse the soft keyboard.

The refresh action waits for current mobile viewport geometry, then force-claims
and redraws the active pane at that measured grid. Scrollback remains lazy and
one-page-per-pane, while page validation, kernel prepend, cursor advancement,
and in-flight release commit atomically without decoding raw bytes to text.

## Acceptance

- A terminal tap raises the system keyboard and it remains open for input.
- The refresh button remeasures the settled current screen, resizes the active
  host PTY/parser, and performs a full local redraw even at the same grid.
- Older history loads only near the top and only one page per pane is in flight.
- Stale, duplicate, malformed, or failed pages neither mutate the kernel nor
  advance the sequence cursor.
- A successful prepend and cursor advancement occur in one synchronous commit.
- Scrollback bytes survive worker validation byte-for-byte.
