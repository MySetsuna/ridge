# Restore mobile Remote with WebGL2 fallback

## Confirmed defect

Remote uses one WebGPU-only `wgpu` instance and requests an adapter before a
compatible canvas surface exists. Physical LAN pages commonly lack
`navigator.gpu` because WebGPU requires a secure context; older iOS and some
Android devices also expose no WebGPU adapter. The terminal therefore stops at
`WEBGPU_INIT_FAILED` although WebGL2 is available.

## Rationale

Compile `wgpu`'s WebGL backend and use its WebGPU-detection constructor. This
keeps the existing Rust renderer, shaders, atlas, compositor, and JavaScript
API intact; a separate WebGL renderer would duplicate substantial behavior.

## Acceptance

- WebGPU remains first choice where a real adapter is available.
- With `navigator.gpu` absent and WebGL2 present, a terminal attaches, paints,
  accepts input, and reports `WebGL2` without a WebGPU failure alert.
- Surface format comes from adapter/surface capabilities and supports both
  BGRA and RGBA browser canvas formats.
- Canvas2D remains glyph-rasterization input only, never presentation.
- With neither WebGPU nor WebGL2, initialization fails once with actionable
  diagnostics rather than an endless loading state.
- Rust, WASM, manager, Remote, desktop WebGPU, and mobile-emulation gates pass.
