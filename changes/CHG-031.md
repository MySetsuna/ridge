## §2 修版本口径

按 Goal §2：

- **真实来源**：发布版本由根 `package.json` + `src-tauri/tauri.conf.json` 决定（0.1.86，
  已 CHG-028 锁定）。CLI `--version` 走 clap `#[command(version)]` → `CARGO_PKG_VERSION`
  → `packages/ridge-cli/Cargo.toml`（0.1.0）。

  这是发布策略选择（产品版本与库 crate 版本解耦），不是构建来源漂移。
- **构建来源证明**：commit `667d8389` 同 checkpoint 出 4 件产物，
  SHA-256 + git diff 出货时核对。
- **不改协议版本** / **不全局升级依赖** / **不冒认已正式发布**。

## §3 修 smoke 验证口径

按 Goal §3：

- `/v1/health` 由 `packages/ridge-kernel/src/server.rs` 定义，**不**被 Remote Host 路径
  fallback。Remote Host 应走 `/` (SPA) 或独立 `/health` 路由，**不**应与 Kernel `/v1/health` 同义。
- 重写 smoke 脚本核对：
  - Kernel 真实路径：`127.0.0.1:<kernel_port>/v1/health`、`/v1/status`（需 token）；
  - Remote Host 真实路径：`https://127.0.0.1:<host_port>/`（SPA）、`/health` (如存在)；
  - 验证响应 JSON 内容（role/host_id/runtime_epoch），不只看 HTTP 200。
- 确认运行中的 kernel 是从本候选启动（pid 文件 + 数据目录 + RIDGE_KERNEL_DATA_DIR），
  不是已安装的旧实例。

`reused_live_pid` 测试：定点核对 `ensure_rdg` 改 status-only 后仍证明：

1. 旧 PID（registry 中登记的）仍存活 → `is_process_alive(stale_pid) == true`；
2. 新 kernel 启动后 pid 与 stale_pid 不同 → `endpoint.pid != stale_pid`；
3. registry 已替换 → `data_dir/kernel.json` 重新写入新 pid；
4. 旧 PID **未被杀**（契约要求，不能误杀未知进程）。

不通过弱化断言让测试变绿。

## §5 完成可自动执行的使用验收

按 Goal §5：

- 在两种 Web UI（mobile / desktop）走通：认证 → 列 → attach → 输入/输出 → resize → 重连。
- 快速 A→B→A 切换 / 旧响应晚到 / 浏览器历史切换基线自动跑，不全归为「缺真机」。
- 真机仅留：断网/锁屏恢复、输入与切换归属、滚动/选择手势、100–5000 行切换；
  PWA 实际安装/更新单独记录。
