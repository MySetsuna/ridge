# Global Commune agent projections and resilient Remote recovery

User explicitly clarified that Commune aggregates Agents from every workspace and has no current-workspace product filter. Preserve exact source workspace/pane/session identities internally for authorization and actions. Make members, recent protocol replies, history and existing groups available globally; do not silently rebind identities or merge stored permissions. Fix assistant agentMessage items excluded by the UI query/model, preserve confirmed roster/approval snapshots on transient read failures, and fence obsolete async reads. Repair Cloud reconnect flapping recovery, Kernel notification hello negotiation and native JSON-RPC unsubscribe cleanup. Verify with deferred failure tests, real Kernel WebSocket/integration tests, owned protocol fixture UI, and current authenticated desktop/mobile Remote scenarios; measure local latency with explicit build/route and physical-device/WAN gaps. User authorized continued improvement and the existing metadata exception. No release requested in this round.


## Implementation and verification record (2026-10-27)

- Commune presents all authorized sources, independently of the active terminal workspace. Desktop includes discovered terminal Agents and registered protocol members; current Remote trust policy exposes registered protocol members only. Source workspace/pane/session/process-generation identifiers remain internal action and permission bindings.
- Recent assistant reads filter before the bounded history limit and accept both ACP agent_message_chunk and app-server agentMessage. Per-source recent/history cursors, retained confirmed snapshots, closed-source pruning and generation fences prevent cross-source misbinding and stale refresh overwrites. History failures are isolated: healthy sources keep updating, failed cursors retry without duplicate consumption, failed-source confirmed rows remain visible for the same query, and partial results show an error.
- Remote global roster remains mounted across terminal selection changes. Agent navigation serializes latest selection; pending attention retains exact owners. Shared QueryClient work no longer captures the cancelled observer signal (the native browser acceptance reproduced an initial AbortError before this repair). Concurrent observers now cancel independently.
- Cloud recovery serializes the latest reconnect intent and rejects stale authentication completions. Kernel handles notification hello negotiation and per-connection native unsubscribe. WebGL context event listeners use capture; actual GPU context-loss recovery remains unverified.
- Remote group task controls now call existing Runtime methods. Kernel canSend/canCancel reflect existing method capabilities rather than equating permission with native trust; existing non-native send/cancel integration succeeds without exposing native process discovery. Existing groups retain their original storage/authorization scope; cross-source single-group execution and a single global group builder are still incomplete.
- Native LAN startup reproduced Windows reserved/default port failure. Omitted-port startup may use an OS-assigned port after the existing default range fails; explicit requested ports retain failure semantics. Actual native CDP enabled HTTPS/WSS on a nonzero fallback port.
- Continuous Kernel regression CI now runs registration, group-task and Remote invoke tests. The obsolete desktop CLI workflow is archived under docs/archive/CHG-084; the active workflow runs the independent Kernel tests and uploads logs only.
