# Reinstall the scoped E2E CA after host restart

## Semantic delta

The real-browser E2E harness shall reinstall the freshly booted host CA into
the current user's Root store after each intentional host restart before
opening the next browser leg. It shall continue using the existing scoped
CurrentUser trust flow, without certificate-error bypass flags, machine trust
changes, or product TLS changes.

## Acceptance tests

1. A full headed `scripts/browser-ui-e2e.mjs` run can navigate both the mobile
   and desktop legs after the desktop host reboot under normal certificate
   validation.
2. The script still removes the test CA on exit and never writes HKLM or uses
   `ignore-certificate-errors`.
3. Existing sent/echo/desktop-feed, resize, reload, trust-scope, and failure
   reporting gates remain unchanged.
