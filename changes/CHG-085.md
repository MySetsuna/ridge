# Research, plan and design

User requested closing the named gaps, with research/planning/design before development. Existing authorization to fill change metadata applies. Goal: Host-global Commune without a workspace product filter, truthful Remote candidate capabilities, reliable terminal GPU recovery, and evidence that separates local simulation from external/device acceptance.

Research: global views currently wrap source-local group editors; group authority, parent task reservation and frozen-context lookup are workspace-indexed. Native discovery includes process instances and terminal text; Remote deliberately returns none. The shared GPU canvas lives outside pane containers; context-restored only requests redraw, while component parking retains invalid render handles. A2A already has an authenticated Hub adapter and a version-aware client; no duplicate protocol implementation is justified. Official ACP v1 uses spawned stdio/custom transports (HTTP remains draft), so ordinary CLI support does not imply attachable protocol support. Official A2A capability/version negotiation and WebGL invalid-resource restoration rules remain binding.

Design and sequence:
1. Establish Host-global group scope over the existing Kernel authority/Hub, preserve every child source identity, retain historical scopes and immutable running tasks. Read without migration; first explicit edit archives original authority and commits a compatible global snapshot atomically. Single global editor on both clients, shared task controls.
2. Expose a bounded read-only Remote terminal-candidate projection, stripped of process/configuration secrets; locate through existing authorized terminal control. Native-only methods remain native-only.
3. Move canvas recovery to the shared manager, rebuild GPU host/render handles with generation fences while preserving kernels, streams and input ledgers; real browser loss/restore and failure/retry regression.
4. Reuse independent official A2A SDK for protocol interoperability; require an actual running external Agent to claim Agent acceptance. Validate actual available device/network routes separately. ADB currently lists no device; default Python lacks a2a-sdk, so inspect the existing isolated SDK environment before installing anything. No real external Agent endpoint has yet been established.

Acceptance includes two-source exact target/group task integration; migration/commit failure/restart/idempotency; non-native candidate redaction and forbidden-method rejection; desktop/narrow UI group flow and selection independence; actual WebGL loss/restoration, pane-switch and keyboard round trips; required repository checks and SpecTree verify/complete. No speculative provider adapter, new Agent/LLM session or broad trust escalation.

Research references: https://agentclientprotocol.com/protocol/v1/transports ; https://a2a-protocol.org/latest/specification/ ; https://registry.khronos.org/webgl/specs/latest/1.0/ . Current WebGL latest is a draft; restoration invariants are also present in the published 1.0.3 specification.

## Implementation and findings

The core migration had left group ownership and MCP self-join indexed by workspace. A single Host projection/editor now reads every source, reserves global parent tasks and freezes each child's real source identity. Legacy reads do not migrate; the first explicit edit archives the exact original bytes, uses revision compare-and-swap and atomically publishes the new authority. Colliding legacy IDs and archived IDs remain distinct; offline references, historical tasks and restart recovery survive. Legacy authority cannot create new tasks after migration. The internal Host storage key cannot pass as a workspace ID. Both clients and pane badges share the same group authority; unchanged rename-field blur performs no write.

Remote individual sends still used obsolete snake_case target fields while the Kernel parser consumes camelCase. LAN and Cloud now send the current contract. Previous ACK mocks missed the mismatch; regression checks inspect the payload, and the production narrow UI delivers one message to the original ACP fixture exactly once. Remote also projects ordinary process candidates through an explicit six-field whitelist and a 4096-character text cap. Process instances, arguments, endpoints and configuration remain absent; native-only manual terminal interaction stays denied.

GPU loss previously invalidated the shared host resources while pane restoration reused old handles. The manager now owns real shared-canvas events and rebuilds only GPU resources, preserving kernels, subscriptions, terminal epochs and input ledgers. Recovery is serialized and generation-fenced; parked panes rebuild on mount, closed panes cannot return, and failures expose a retry. Desktop and Remote subscribe to the same error/retry state. No Rust/WASM terminal implementation change was needed.

The old JS Cloud terminal harness invokes retired subscription methods and is not the production Cloud owner. Its exploratory failure was not counted as a production failure or acceptance. The current Kernel-owned Cloud test passed without adding obsolete IPC. An unsubscribe integration fixture also depended on interactive PowerShell startup CWD escaping its intentionally narrow filesystem grant; it now uses an explicitly rooted owned shell, preserving production sandbox rejection.

## Acceptance evidence and limits

Local evidence is retained under ignored `artifacts/commune085/`; credentials and endpoint files are excluded from Git. Browser GPU injection uses Chromium WebGL2 through SwiftShader, a software GPU backend; it does not validate a physical GPU/driver. Final commands and results are recorded below when complete.

- `global-ui.json`: seven checks pass against the actual Kernel and production desktop/narrow Commune components: two-source members/history, one cross-source group editor, real group dispatch, ordinary candidate redaction, individual protocol delivery, workspace-selection independence and one-source failure/retry isolation. The narrow Cloud connection uses the real Runtime facade; this does not establish hosted Cloud network behavior.
- `remote-desktop-final.json` and `remote-mobile-final.json`: respectively 11 and 9 browser checks pass over real LAN HTTPS/WSS with compiled production UI. Both perform two actual `WEBGL_lose_context` cycles, including switching away during loss and returning after restoration. Kernels and epochs remain stable; activation stays stable without a source switch, while normal reactivation on return is allowed. Distinct keys reach the real PTY without duplication. Lazy-load retry, dead-socket recovery, soft deletion/newline and supported pointer encoding pass. The final production rebuild restores release WASM; these live probes used the isolated current-source dev Kernel and its previously built UI assets, not a release installer.
- The X10 fixture requires a wide shared grid. After workspace switching, the native viewer's delayed layout fit can reclaim a 51-column grid; the probe now waits for the actual native layout timers, explicitly claims the Remote viewport, and observes 163 columns before testing a high coordinate. Normal focus reports are settled separately from the no-duplicate-key assertion. These fixture corrections do not establish concurrent-viewer resize arbitration under WAN delay. Windows ConPTY/Node still converts legacy non-UTF8 X10 input; transport bytes and SGR input are verified, arbitrary-byte child delivery is not claimed.
- `kernel-cloud.log`: actual browser/Rust WebRTC, signed E2EE, TOTP/trust resumption, loopback projection, reconnect, canonical terminal frames, same child input and explicit offline pass against an owned local signaling/API fixture. Hosted relay/TURN/WAN coverage remains unverified.
- `sdk.json`: official independent `a2a-sdk` 1.2.2 passes discovery, send, task read, context isolation and cancellation against the actual Hub and an owned existing ACP process. Delivery acknowledgement is not objective completion. This proves SDK interoperability, not acceptance against a real external Agent.
- Windows and Linux: Kernel library 224 tests, group integration 2, registration/retirement 2 and Remote invoke/notification 3 pass. MCP library 120 tests pass. Two ignored test-process entry points are explicit helpers, not omitted assertions. The final Host scope guard is covered by the group integration rerun.
- `multitab-final.log`: actual native CDP UI opens three workspaces (1 → 2 → 3), keeps one shared canvas, and reports no uncaught exceptions or long tasks. The observed worst local event-loop stall is 14 ms; idle p95 is 12 ms. This small dev workload is not a device, load or network performance guarantee.

Remaining acceptance gaps: ADB has no physical handset; no running external Agent protocol endpoint was supplied; hosted relay/TURN/WAN and WebGPU device-loss injection are unavailable. Do not mark the entire Commune/Remote product fully validated from these local results. The user was asked for device/endpoint availability while independent local work continued. No new provider session, model call or release publication was initiated.

Final repository checks: `npm test` passes (2162 tests, 14 explicit skips, plus six walker tests); `npm run lint` and `npm run typecheck` each report zero errors/warnings. `stc verify CHG-085 --run-tests` is valid with no diagnostics or unauthorized paths, trace coverage 1 and testStatus PASS. Release font/render WASM rebuilding and `pnpm build:remote` pass for desktop and mobile, including PWA verification (46 precached entries, 1039.08 KiB). The isolated CDP desktop, its child processes and private Kernel have been stopped; the installed application/session was not targeted. Version remains 0.1.97.
