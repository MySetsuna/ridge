# Unify rounded corner connector profiles

At 19px, the selected Consolas raster produces a one-row opaque `─` connector,
while a rounded corner's boundary arm carries a second low-coverage row. Both
are valid standalone font rasters, but placing them in adjacent terminal cells
exposes the differing edge profiles as a shadow and color step.

Rounded corners must keep their native curves while their declared cell-edge
arms reuse the same selected-font `─` and `│` boundary profiles used by adjacent
straight cells. Resolve those references through the existing Swash system-font
path, cache them per font stack/size/DPR/style, and never substitute procedural
geometry or coverage thresholds.

Acceptance:

- At 19px, real Consolas `╮` left-edge coverage equals real Consolas `─` edge
  coverage exactly after stabilization.
- The same corner's bottom-edge coverage equals real Consolas `│` coverage.
- Synthetic fixtures prove only declared boundary rows/columns change; interior
  curve pixels remain byte-for-byte unchanged.
- Reference profiles are cached per font configuration and cannot recurse.
- Ridge-term WebGPU tests, WASM build, and STC gates pass.
