# Remote mobile fast startup, seamless pane switching, and daily authentication

Remote mobile startup and pane transitions shall remain responsive: terminal/WASM and
secondary UI chunks load only after authentication and when their feature is needed;
pane refresh/switch shall discard stale canvas work before fitting the current viewport.
LAN sessions shall keep device and source-IP binding while allowing one successful
verification to remain valid for 24 hours.

Acceptance:

- Remote entry does not initialize the terminal manager before authentication.
- MainApp does not request optional terminal/sidebar/file-viewer/keyboard chunks until
  connection and feature use require them.
- A pane switch or refresh cannot apply a delayed fit to a different pane.
- LAN session expiry is 24 hours and existing device/IP validation remains enforced.
- `npm test`, `npm run check`, `npm run build:remote`, and `stc verify` pass.
