# 重整 Commune 成员接入、协作入口与编组体验

## 用户问题与根因

用户要求已有会话能接入身份、历史、派发与审批，列表已有成员应能编组，正常操作应直接可见。现状把终端发现与协议登记分成两种集合，编组权威又仅接受 protocol_binding，故用户看到成员却无法选入组。精确会话握手、协议历史、派发和审批已有实现，普通终端发现尚未授予这些能力。

## 已完成范围

- CHG-091 完成 Remote 单成员派发意图和回执恢复。
- CHG-093 完成无需客户端查询的实时 CWD 推送，真实终端 cd 回归通过。
- CHG-094 完成协作入口展开、全部已登记成员及来源呈现、候选说明、成员原子移动和组长处理。
- CHG-097 完成连接文件向导、预览、拒绝后的修正重试及已有进程保活验收。正常路径可选择文件。
- CHG-098 完成组派发回执丢失和重挂恢复，确认原派发保留后续输入。实际 Runtime 与隔离 ACP 会话验收通过。

以上各有独立已激活规范。它们尚未提供“未连接终端直接编组”的稳定组织成员契约，也未证明所有外部 Agent 及真实手机均可互操作。

## 批准方案

推荐沿用现有 agentId，在 commune-groups.json 的 version 3 中增加组织成员名册。终端候选经 Runtime 核验后，创建稳定成员与加入组一次原子提交。后续连接准确原进程的已有 session，复用成员 ID，原组保留。

发现投影为 Native/Remote 提供 opaque 候选引用。Remote 用现有组管理权限完成组织编组，协议登记继续沿用 native 信任边界。标题、目录和同一分屏不能用于自动接续身份。

协议身份继续存于现有 roster，组织名册不伪造 session 或控制租约。不同进程或 session 的重新绑定须由用户显式选择，并通过原任务、审批和运行代际校验。现有任务与历史保留原绑定。

旧组文件先归档再迁移，旧引用保持原 ID。组织成员与编组同处已有文档，可复用原子写入和版本拒绝，避免两文件半提交以及旧 Runtime 静默重写新增记录。

正式字段、操作边界、迁移和验收见 [组织成员规范](../specs/l4-commune-organization-members.md)，应用过的提案保存在 [.spectree/proposals/archive/CHG-092.json](../.spectree/proposals/archive/CHG-092.json)。本文件记录评审状态和范围。

## 实施顺序

1. 组织成员与组事务、旧资料迁移和故障恢复。
2. 可信候选引用与终端成员入组，覆盖 Native、Remote。
3. 既有会话接入保留成员、编组及历史，处理并发和显式重新绑定。
4. 统一成员卡、组选择与能力反馈，再完成用户实际 Agent、手机及路由验收。

## 批准状态

用户已明确采用本草案，复用 agentId、组文件升级 v3，允许终端先编组、接入后保留原组，并按方案归档迁移旧资料。按 SpecTree 门禁实施并验证，外部 Agent 与真机证据依实际环境记录。

## 实施与验收记录

- 已实现 v3 组织名册、可信候选引用、成员入组单次 CAS 与原子提交。旧版本首次组织写入前归档原字节，保留工作区、历史编组和 legacy 原始资料。
- 已实现原进程会话接入复用 agentId、显式重新绑定、归档恢复，以及 Native/Remote 共用的组织成员与能力投影。断开协作、移组、归档分别提供操作。
- 隔离 Runtime 已验证同名来源区分、跨 Runtime 引用拒绝、终端重建和工作区关闭后旧引用失效、双客户端 CAS、入组与握手并发、真实协议审批、旧历史追加保留和重启恢复。
- 解散组的本地确认入口不受后台读取禁用，确认提交仍受写入状态和 CAS 约束。
- 浏览器已验证窄屏 Remote 先给终端编组，再从 Native 连接文件接入同一成员与原组。实际失联后重挂仍能按原派发 key 确认回执，协议请求执行一次。
- 连接文件、显式重新绑定、断开操作及错误提示已提供中英文文案，英文窄屏预览通过，取消预览不改变登记。
- 已通过 Core 全量 381 项单测及 1 项文档测试，以及 npm test、lint、typecheck、移动 PWA 与桌面生产构建。最终 SpecTree 门禁结果以本变更的验证记录为准。

## 验收边界

以上协议进程由隔离 fixture 提供。用户实际外部 Agent、真实手机、LAN 和 Cloud 网络互操作仍待实际环境验收。

隔离接入曾在 UI 启动前返回 `protocol socket belongs to a different process`。失败记录保留于 `artifacts/commune092/global-ui-attestation-failure.json`。Windows 检查已区分连接归属尚不可观察、错误 PID 与歧义归属，前者在同一 socket 上最多观察等待 100 ms，每次核验原进程启动实例，后两者立即拒绝。确定性表样本、真实连接建立后 accept 前的连续校验，以及无归属超时不授予控制权均纳入回归。此前失败未记录实际 TCP 表状态，无法追溯确认是否命中该观察窗口。
