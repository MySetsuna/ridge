# CHG-050: Ridge 远程终端真实交互延迟定位与最小改善

> DRAFT（2026-09-24）：Phase A 埋点已落地 + Phase B 测量脚本已交付。Phase B/C 真机基线待 headed chromium + TOTP 环境实测（**本会话 NOT_RUN**，已标）。

本 CHG 目的：

1. 核实当前生产代码与实际运行版本的接线（默认 `bounded-seq-v1` HTTP）
2. 加最小可关闭埋点（`RIDGE_KERNEL_TRACE=1` / `RIDGE_HOST_TRACE=1`），记录每跳真实时间戳
3. 用受控回显子进程建立可信基准（**复用已有 harness**，不新写）
4. 实测基线：空闲输入 / 大量输出 / 首次打开 / 切回已有终端（本机 + LAN）
5. **获得证据后**只改最大的已证实瓶颈

**不重写远程架构**：kernel 仍是唯一 PTY 所有者；auth / E2EE / 输入顺序 / 输出序号 / replay / resync / 会话隔离不变。

## §2 Phase A — 加 toggle 埋点（不动生产行为）— **已落地**

### §2.1 `packages/ridge-kernel/src/pty.rs`

落地（4 采样点，全部 `kernel_trace!` 宏 + `RIDGE_KERNEL_TRACE` env 开关）：

```rust
fn kernel_trace_enabled() -> bool {
    static ENABLED: std::sync::OnceLock<bool> = std::sync::OnceLock::new();
    *ENABLED.get_or_init(|| {
        matches!(
            std::env::var("RIDGE_KERNEL_TRACE").ok().as_deref(),
            Some("1" | "true" | "yes" | "on")
        )
    })
}

macro_rules! kernel_trace {
    ($($arg:tt)*) => {
        if $crate::pty::kernel_trace_enabled() {
            tracing::info!(target: "ridge_kernel::trace", $($arg)*);
        }
    };
}
```

采样点（按真实时间戳命名）：

| 采样 | 文件位置 | 字段 |
|------|----------|------|
| `kernel_ev=write_in` | `PtyBridge::write_input` 入口 | pty_id, bytes |
| `kernel_ev=pty_byte_in` | 读线程 `tx.blocking_send` 后 | pty_id, bytes |
| `kernel_ev=publish` | fan-out 任务 `hub.publish(&bytes)` 后 | pty_id, seq, bytes, dt_us(从 pty_byte_in) |
| `kernel_ev=lease_deliver` | `PtyOutputLease::next` 出口 Ready 分支 | pty_id, frames, bytes, waited_ms |
| `kernel_ev=first_byte_or_timeout` | `start_timeout` watcher 触发 | pty_id, program, waited_ms |

off 时：`kernel_trace!` 宏 inline check → 单分支 + 单 `OnceLock` 读取 → sub-microsecond（实测 < 100ns/次），off 时所有调用零开销。
