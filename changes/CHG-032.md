# v9-16 Desktop Web Remote LAN 输出订阅与 mobile 契约对齐

> DRAFT（2026-09-18）：用户已批准 scope（v9-16 指令），待正式 gate 审批后方可 lock。
> 本变更不修改任何已冻结 L2 协议契约（L2-PROTO/REMOTE/TERM/PERF-001 均不在 affects），
> 不新增 transport/runtime，不改 wire shape。

## 根因（v9-16 已复现，见 artifacts/release/v9-16-desktop-io-report.md）

- Desktop Web Remote 输出订阅走 `TauriBridge.subscribePane`
 （`src/lib/transport/tauriShim/bridge.ts:192-196`）→ `RpcClient.notify('subscribe-pane')`
  → `LanWsAdapter.sendControl` → `RemoteConnection.send({type:'subscribe-pane',…})`。
  该路径从不调用 `RemoteConnection.subscribePane()`，故 `_setPaneRef`
  （`packages/remote/src/shared/transport/wsRemote.ts:710`，全仓唯一调用点
  `wsRemote.ts:1466`）永不执行 → `paneKeysById` 恒空 →
  `_handleBinaryMessage`（`wsRemote.ts:947-972`，`keys?.size !== 1` 直接 return）
  丢弃 host 下发的全部 16B-UUID `pane_frame` 二进制帧 → 页面永远显示不出 marker。
- INPUT 路径正常（`write_to_pty` → `invoke-request` → `kernel_host_impl` dispatch），
  mobile 正常（直调 `conn.subscribePane` 已注册）。断点 100% 在 OUTPUT 侧。
- `kernel_host_impl.rs:897` 的 4 个缺失方法、`RidgePane.svelte:1786` attached 门、
  `tauriShim write_to_pty` 均已证实非阻塞，本变更一律不动。

## 修复设计（只动 L3-TRANSPORT 拥有的两个文件）

1. `packages/remote/src/shared/transport/lanWsAdapter.ts`
   - `sendControl` 截获 `method === 'subscribe-pane'` 的 JSON-RPC notification：
     改调 `this.conn.subscribePane({paneId, workspaceId}, {resume, sinceSeq, active, activationId})`
     **代替** `conn.send`。`subscribePane` 内部发送的 `{type:'subscribe-pane', paneId,
     workspaceId, …opts}` 与今日 `toWire` 展平结果是同一线形（解析后 JSON 一致；
     键序可能不同，语义无关，host 侧按字段解析），故**无双发、无 wire 变更**。
     `paneId`/`workspaceId` 缺失时回退到今日直发行为（与现状一致的 no-op）。
   - 截获 `method === 'unsubscribe-pane'`：先调新增的 `conn.unregisterPane(pane)`
    （见 2），再按今日形状 `conn.send` 转发（host 今日忽略，未来兼容）。
2. `packages/remote/src/shared/transport/wsRemote.ts`
   - 新增公开方法 `unregisterPane(pane: PaneRef): void`（约 8 行），委托现有私有
     `_deletePaneRef(paneRefKey(pane))`；不存在时 no-op。不改任何现有行为。
3. 对称性（已存在，无需改）：
   - 重连：bridge `RpcClient.onReconnected` 重发 subscribe notify → adapter 重走
     `subscribePane`（`_setPaneRef` 幂等）→ 映射重建。
   - 关闭：`LanWsAdapter.close()` → `conn.disconnect()` 已清空
     `paneRefs/paneKeysById`（`wsRemote.ts:2037-2038`）。
   - mobile 路径从不构造 `LanWsAdapter`，零行为变化；`_handleBinaryMessage` 本体不动。
