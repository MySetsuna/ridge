# 统一 CLI 独立终端创建入口

用户于 2026-11-06 确认应用提案、绑定 affects 并推进批准、锁定、实施与验收。行为契约为 `L3-CLI-INDEPENDENT-TERMINAL-CREATION`。docs 架构导览与历史规范映射各自登记后续变更。

## 实施范围

TUI、仪表盘、仅 LAN 和显式指定 shell/CWD 的 Cloud 启动共用 Runtime 创建命令。每次新建保有独立工作区及首个终端，重试携带同一身份与 Runtime 代际。TUI 先完成本地授权和 WebSocket 握手，LAN 先确认监听可用，Cloud 先收到宿主 welcome。Cloud 创建遇到现役配置冲突时明确拒绝，既有服务继续运行。

Kernel 串行处理创建、重放与关闭，复用 PTY 注册表和工作区图。PTY 启动失败保留原状态，工作区保存失败回收本次 PTY。已提交后掉线可按原身份恢复，过时代际和已关闭终端重放显式报错。Host 快照读取按当前状态投影，创建统一由显式命令触发。客户端选择分别绑定自己的连接。

## 验收依据

`packages/ridge-cli/tests/cli_terminal_create_e2e.rs` 使用独立数据目录、真实 Kernel、真实 CLI 伪终端及本地 Cloud 鉴权夹具，覆盖四入口创建、TUI 输入与显示、多会话、独立观察客户端、拒绝授权、监听及 Cloud 鉴权失败、PTY 启动和保存失败、丢失响应、并发重放与原终端往返。过期授权记录由共享授权验证器的独立回归测试覆盖。

SpecTree 的 acceptance_checks 绑定上述两项验收。另执行 Kernel/CLI 单元测试和拓扑、远程调用、认证、工作区连续性、终端生命周期回归，以及 npm test、lint、typecheck。验收范围为本机 Windows、拥有的 Runtime 和本地 Cloud 夹具。
