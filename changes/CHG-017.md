# Close terminal startup, font, and verification gaps

This closeout batch absorbs the verified terminal changes since `CHG-014`:
native-size glyph presentation, bounded renderer probes, real initial PTY
geometry across desktop and Remote hosts, acknowledged input writes, and
isolated native WebView2 coverage. It also restores the `v0.1.70` font-byte
pipeline: Host resolves the selected system mono, CJK, symbol, and color-emoji
faces; desktop installs them directly into cosmic-text/Swash, while an
authenticated Remote receives the same bounded payload through the existing
LAN/WebRTC RPC path and caches it by Host/font hash. Remote must not request
Local Font Access, require font installation, or fall back to line-art emoji.
Cloud transports encrypted bytes only and never persists font payloads.

The retired project-local WebView2 E2E
profile is runtime state already covered by `/.webview2-*` in `.gitignore`;
exclude its concrete directory from the SpecTree baseline.

## Acceptance

- `stc audit --all` reports no findings.
- DPR 1 and 1.25 WebGPU glyph fixtures retain CJK, symbols, emoji, and clusters.
- Text, box drawing, symbols, and emoji all use Swash-rasterized Host font data;
  no terminal production path creates a browser 2D context.
- Box connectors copy the selected font's own coverage into line-height slack;
  they never force opaque endpoint pixels or overlap adjacent rows. Rounded
  corners remain anti-aliased without gaps, doubled strokes, or shadow edges.
- Desktop and authenticated Remote render Host color emoji from the same font
  payload without Local Font Access or additional device font installation;
  color-glyph RGBA channels remain non-gray through atlas upload and WebGPU.
- Font RPC rejects untrusted family input, bounds face count/bytes, and is
  admitted only after existing LAN/Cloud authentication; Cloud stores no font.
- Native shell E2E passes without duplicate prompts, lost input, cursor overflow,
  or test-owned process leaks.
- Production launches do not expose the mutable E2E hook.
- The existing physical-device draft remains open pending real hardware and a
  public-network path.
