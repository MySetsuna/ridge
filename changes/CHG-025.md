# Align rounded corner vertical tangent

Rounded box corners currently align their full native bitmap only to the
horizontal straight-glyph axis. The pure vertical arm is then replaced with
the selected font's vertical profile on a different x axis, leaving a one-pixel
back-step where the native curve enters the rebuilt arm.

Align the complete native corner bitmap to both selected-font straight axes.
Rebuild only the straight connector spans affected by that rigid translation,
using the original `─` and `│` raster profiles. A vertical tangent row that
has not yet gained coverage toward the curve interior also reuses the `│`
profile; replacement stops at the first inward curve pixel. Keep the curve's
remaining native antialiasing and one-source-texel-to-one-device-pixel WebGPU
sampling.

Acceptance:

- All four rounded corners use the same vertical axis as the selected font's
  `│` glyph before their straight arms are rebuilt.
- The curve-to-vertical transition advances monotonically into that axis; it
  does not step away and then return on the first rebuilt row.
- Outer hook rows are rebuilt only until the first row that extends toward the
  curve interior; right-hand corners that are already monotonic remain intact.
- Horizontal and vertical arms still match selected-font `─` and `│` profiles
  for regular and bold Consolas at 19 px.
- No procedural box drawing, alpha thresholding, bitmap scaling, Canvas2D, or
  non-WebGPU presentation path is introduced.
- Focused rasterizer tests and the complete `ridge-term` suite pass.
