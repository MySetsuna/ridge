# Make kernel host snapshots lazy around PTY input

The kernel-backed LAN host shall not perform a synchronous global workspace
snapshot before processing every WebSocket message. PTY input requests carrying
an explicit pane identity must reach `write_to_pty` without waiting for an
unrelated topology/control projection; messages that need workspace topology
shall retain their existing snapshot-backed validation.

Acceptance:

- `write_to_pty` invoke requests receive a reply and the requested PTY echoes a
  unique marker through the real browser transport.
- Desktop `manager.feed` observes the same marker after the shell executes it.
- Existing auth, pane attach, resize, reconnect, and trust-scope checks remain
  valid.
- No mock, UI injection, transport bypass, TLS bypass, or frame-count-only gate
  is introduced.
- `stc verify` and the focused kernel-host test pass; full project gate results
  are reported.
