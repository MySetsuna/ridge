# 分离 Commune 编组读取与写入状态并完善可恢复交互

用户已授权实施后续迭代计划，并明确允许仅补写本变更的 affects 与变更说明，再重新审批、加锁。规范正文已通过 SpecTree 提案应用，实施与验收以 L4-COMMUNE-GROUP-RESPONSIVE-STATE 为准。

## 变更范围

- 分离首次加载、后台读取与写入状态，避免后台刷新间歇禁用编组操作。
- 初次取得有效投影前禁止写入。已有投影时继续使用最后确认 revision 经过 Runtime CAS，写入保持串行。
- 旧读取、失败回包及旧作用域请求不得覆盖新写入结果、错误或状态。重复刷新合并，失败保留投影并可显式重试。
- 保留 legacy 迁移互斥、成员身份、组织持久化、派发恢复及历史契约。
- Native 与 Remote 共用加载、刷新、保存和错误反馈，提供中英文与无障碍状态，核对窄屏布局及触摸尺寸。

## 验收

- 单测控制读写 Promise 顺序，覆盖初次加载失败、后台读取中写入、过期读取成功及失败、重复刷新、竞争写入、作用域切换和 legacy 迁移。
- 浏览器挂起生产组件的后台读取，完成真实隔离 Kernel CAS 写入，再释放旧快照，确认新投影保持，并回归编组、派发、审批、接入与窄屏显示。
- 执行 npm test、npm run lint、npm run typecheck，以及 SpecTree verify、complete。
- 协议与浏览器证据来自隔离 Kernel 和自有 fixture。实际外部 Agent、手机及公网互操作另行验收。
