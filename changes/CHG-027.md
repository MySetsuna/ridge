# Preserve Remote pane resize ownership and prove in-place TUI redraws

The LAN hosts currently acknowledge `resize_pane` without the initiating
`owner`. The browser transport therefore treats a Remote-owned mobile claim as
Host-owned even though the claimed rows and columns came from the phone. Keep
the request owner on every `pty-resized` acknowledgement; unknown values fail
closed to `host`.

The mobile LAN shell also renders its terminal before attaching the authenticated
RPC bridge, so Host font discovery can fail before WebGPU initialization. Attach
the bridge synchronously at the verification boundary, before exposing MainApp.

Add production-bundle evidence for the actual failure mode. A real `rdg tui
--lan-host` PTY and mobile Chromium controller must agree on the pane-box grid,
and repeated primary-screen cursor-addressed TUI frames must update in place
without increasing the browser kernel scrollback or moving its viewport.

Acceptance:

- LAN RPC and legacy resize acknowledgements include `owner`; a Remote claim
  round-trips as `remote`, while missing or invalid input defaults to `host`.
- Cloud keeps its existing owner-preserving `pty-resized` path.
- LAN Host font discovery starts only after the authenticated bridge is attached.
- Desktop, Cloud, LAN `rdg`, and kernel Host font RPCs share one bounded resolver.
- The GL-compatible cell shader uses one atlas sampler: color glyphs remain
  linearly filtered while monochrome text and cell graphics use exact texel loads.
- RIDGE_DIAG geometry reports bounded scrollback and cursor state for the real
  browser probe without exposing it in normal sessions.
- The production `remote-dist` mobile probe observes one Remote-owned claim
  whose rows and columns equal both the reported and kernel grid.
- After a fixture clears history and announces readiness, at least 100
  cursor-addressed primary-screen redraws leave scrollback length and offset
  unchanged and render the final marker.
- Focused LAN host, Remote, terminal, production build, and STC gates pass.
